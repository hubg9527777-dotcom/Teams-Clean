# Teams Clean 6.3.1

用于 `https://teams.live.com/` 的 Chrome / Edge 扩展，清理个人 Teams 的聊天、联系人与铃铛活动列表。

本版重点：聊天接口优先；录制按具体记录和控件定位；确认记录移除后计数；已识别错误自动恢复；从顶部开始并复扫三遍。**扫描结束不等于所有项目均删除成功**，请查看未完成和待核对数量。

## 安装或升级

1. 解压安装包，保留整个 `Teams-Clean-v6.3.1` 文件夹。
2. 打开 `chrome://extensions` 或 `edge://extensions`，启用开发者模式，停用旧版，点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的文件夹。
3. 刷新 Teams 网页，面板应显示 `v6.3.1`。6.0.x 及更早版本的录制需重新录制一次。6.3.0 的 rowSchema 3 录制格式兼容；覆盖同一个扩展目录后重新加载可保留原录制。

不要同时启用两份 Teams Clean，避免两个面板或重复操作。

## 联系人、活动及聊天录制后备

1. 手动打开要清理的列表，清除搜索条件，选择面板中的对应区域；聊天需选择“录制后备”。
2. 点击“录制操作”，从**一条记录的右键或更多按钮**开始，完整删除这一条，包括确认弹窗。录制中的删除会立即生效。
3. 等这条记录从列表消失，再点击“保存并执行”，程序随后自动处理其他记录。
4. 后续同样列表直接点击“开始清理”。程序从顶部开始、向下滚动加载，再从顶部复扫，总共三遍。

无需精确复制鼠标轨迹，也不会完整重演录制时的犹豫时间。窗口大小变化后重新计算位置；列表结构变化、切换页面、按钮无法唯一判断时会保留进度停止。

| 情况 | 本版行为 |
| --- | --- |
| 菜单出现慢、按钮暂时禁用 | 等待控件出现和启用，再继续 |
| 已识别的临时错误 | 自动关闭提示，继续其他记录，在后续复扫中重试 |
| 明确拒绝删除 | 不记成功；继续其他记录，每遍重试一次，最多三遍 |
| 已提交但未确认记录消失 | 隔离为待核对，本轮不重复提交；继续其他记录，复扫核对最终结果 |
| 已移除记录重新出现 | 撤回成功计数，转入待核对 |
| 列表加载中 | 等待加载；持续加载则保留进度停止，不当作空列表 |
| 登录失效、未知弹窗关不掉、连续多条结构不匹配 | 保留进度停止，需要处理页面原因 |

“移除已确认”是列表内的界面核验，录制中手动删除的一条不计入自动处理数。刷新后仍应核对 Teams 的同步结果。

## 聊天接口模式

1. 选择“聊天”与“接口（实验）”，点击“1. 开始校准”。
2. 手动删除一条普通聊天，确认成功后点击“2. 手动删除成功，验证一条”。这会自动通过接口验证另一条聊天。
3. 核对验证的聊天已移除，再点击“3. 验证成功，开始清理”。

批量阶段发送已校准的接口请求，从顶部扫描、向下加载并复扫。结果不明的请求隔离，不自动重发，继续其他聊天；单条验证结果不明时仍禁止批量。401 停止并要求重新校准；429 按服务端时间等待，持续限流会保留进度停止。

只有明确拒绝删除的聊天才可进入可选的隐藏阶段；存在未知请求结果时不自动进入隐藏。隐藏不等于删除，有新消息时可能重新出现。未适配的聊天类型单独报告，不按名字猜测是否可删除。

## 暂停、继续与诊断

- “暂停”或 Esc 取消等待并退出；提交后的未知结果保留为待核对。
- 同一页面点击“继续执行”保留进度。结束时有未完成项也保留继续入口；待核对项不会因继续而重复提交。
- 刷新页面结束当前任务和内存进度，不自动启动删除。接口需重新校准，录制配置仍保留。
- 可展开运行日志查看未完成原因；“复制诊断”提供脱敏统计和定位信息，不包含接口令牌和联系人正文。
- 最好把清理页单独放在可见窗口，运行时不操作 Teams 列表。浏览器休眠、页面关闭或后台节流会影响进度。

## 范围与限制

本版没有联系人、铃铛活动的通用接口适配器，不会猜测未知接口。清理范围取决于 Teams 页面提供的操作和能加载的记录；不同类别需分别打开对应列表。它不代表清除了对方副本或微软服务器的全部留存。

同步联系人可能从手机、Outlook 或 Google 再次回流，反复点击不能消除同步源。个人 Teams 的联系人更新也可能延迟。见微软[数据导出与删除说明](https://support.microsoft.com/en-au/teams/free/settings/export-or-delete-your-data-in-microsoft-teams-free)。

微软 Graph 的[聊天删除](https://learn.microsoft.com/en-us/graph/api/chat-delete?view=graph-rest-1.0)和[聊天隐藏](https://learn.microsoft.com/en-us/graph/api/chat-hideforuser?view=graph-rest-1.0)文档均列明不支持个人 Microsoft 账号。本扩展仍使用手动校准的聊天私有接口，不能保证微软未来更新后无需调整。

## 测试

Node.js 22 或更新版本执行 `node --test tests/*.test.cjs`，无需安装 npm 包；打包和打包回归测试需要系统提供 zip / unzip。

100 项回归和隔离 DOM 模型测试通过，覆盖菜单延迟、错误恢复、拒绝项继续、结果隔离、复扫、暂停、设置弹窗内列表、分组树、接口校准和安全边界。**未使用真实 Teams 账号做安装与清空验收**，模型测试不证明当前 Teams 页面一定兼容。

`tests/browser-fixture.html` 提供无账号、无 Teams 请求的人工测试页，使用假存储，不能代替真实扩展安装验收。本轮环境阻止了本地页面的浏览器访问，因此未完成该浏览器测试。

## 安全维护

本版安全修复详见 `SECURITY-AUDIT.md`。面板使用 closed Shadow DOM 减少页面直接读取、改动内部控件的机会；它不能把宿主页面变成可信安全沙箱。接口模板在成功使用后保留五分钟，过期会清除并要求重新校准。切换 Teams 账号后应主动重新校准。

发布前执行 `GITHUB_REF_NAME=v6.3.1 node scripts/package.cjs`，生成仅含运行文件的 ZIP；标签必须与 manifest 版本完全一致。可用 `node scripts/security-scan.cjs` 重跑不输出凭据原文的轻量扫描。该扫描不替代专业扫描器或安全测试。
