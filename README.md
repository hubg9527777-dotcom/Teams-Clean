# Teams Clean v6.0.5

这是对 v6.0.4 的安全审核修复版。按照开发者确认，移除网页 MAIN 脚本和 postMessage 消息桥，仅保留浏览器捕获的 Groups DELETE 接口与录制模式，网络权限收缩为准确的 `https://teams.live.com/*`。不再支持网页 Middle Tier 请求捕获，也不再诊断其他微软域名。

聊天先尝试接口删除，包括“只有我”。删除扫描结束后，默认通过右键菜单隐藏明确拒绝删除的记录。结果未知、超时、认证失效不会直接当成“不能删除”。联络人和活动继续各自的坐标及录制间隔。

## 安装更新

1. 停用旧版插件，解压 v6.0.5；Chrome / Edge 扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，选本目录。覆盖旧安装目录时须删除已取消的 `api-main.js` 并点扩展重新加载，建议直接选择本目录。
2. 刷新 Teams 网页，确认面板日志显示 v6.0.5，重新校准。不要同时运行旧新版。
3. 分别手动打开聊天、联络人、活动页并选择用途。同一区域只允许一个分页执行；不同用途可以同时执行。

无需安装依赖或构建。最低兼容 Chromium 111，但应使用仍有安全更新的 Chrome / Edge。更换扩展身份时旧录制存储可能不会迁移，请重新录制。

## 聊天三步

准备：打开聊天列表，选择“聊天 → 接口（实验）”，默认勾选“删除结束后隐藏明确无法删除的聊天”。

1. 点“1. 开始校准”，两分钟内手动完整删除且只删除一条普通聊天。
2. 确认这条从列表移除，点“2. 手动删除成功，验证一条”。插件实际通过接口删除面板提示的另一条；不是只测试连接。
3. 核对接口验证的另一条也移除，点“3. 验证成功，开始清理”。随后自动尝试删除已加载且与校准模板同类型的记录；结束后才隐藏明确被拒绝的记录。

没有普通聊天或可验证对象时先滚动加载再重新校准。只捕获且验证本分页实际成功的空正文、无查询参数 Groups DELETE 请求。不从 Cookie 猜测令牌，未归属分页的 Worker 不作为模板。

接口常规每条间隔一秒；429按服务端要求等待。401立即停止；连续三条404/410停止；超时、未知返回或过大的正文停止并标记待核对。只有本轮明确被拒绝删除的200业务错误或400/403/409/422进入隐藏队列；本轮有待核对记录时不自动启动隐藏。

隐藏按当前聊天行的右键菜单中精确的“隐藏 / 隱藏 / Hide”点击，不按名称猜测。菜单未出现或点击后不能确认移除时暂停，不虚报成功、不重复发送结果不明的点击。隐藏不是删除，收到新消息时记录可能再次出现。

## 暂停与继续

点“暂停”，等显示已暂停后点“继续清理（保留进度）”。保留删除和隐藏进度，不重发成功及待核对记录；隐藏阶段继续不会重新跑删除阶段。暂停不撤销已提交的请求。

认证模板只保留当前分页及扩展后台内存，不写入存储、不导出、不通过网页消息交付。后台休眠不会清空当前分页副本。刷新或实际401后须重新校准；切换账号后请刷新并重新校准。浏览器丢弃或冻结分页仍可能中断或延迟任务。

校准单条验证被暂停且结果未知时不能直接启用批量；先核对，再重新校准。

## 联络人、活动及聊天录制后备

1. 手动打开对应页并选择用途；聊天后备还需选“录制后备”。保持窗口大小及缩放不变。
2. 点“录制操作”，手动完整删除一条，包括确认。
3. 点“保存并执行”，立即回放后续记录；已有录制可点“开始清理”。暂停后点“继续执行”。

固定位置模式仅计回放轮数，不等于已删除条数。定位失败暂停；联络人和活动无法可靠跳过明确拒绝的记录时暂停。自动末尾隐藏仅用于聊天接口模式。

## 安全审核与限制

安全修复还包括：只允许真实用户输入操作面板、严格校验后台消息的扩展身份及主框架/文档归属、接口目标固定为准确的 Teams origin、200响应流式限制64KiB、处理超长限流等待、防止任意DOM属性进入脱敏诊断、显式本地脚本CSP和敏感文件忽略规则。

面板及回放仍依赖 Teams DOM；不能宣称能抵御已完全控制 Teams 同源页面的攻击者。这个接口是私有服务请求，没有长期兼容保证。仅覆盖当前加载且适配的聊天类型，不保证全部账号历史已清空；结束后刷新核对。

65项测试通过，另有本地浏览器虚拟数据的三步和删除后隐藏回归截图。没有在真实 Teams 账号运行安全测试，安装后须重新完成单条验证。移除11项MAIN测试，保留52项回归并新增13项安全及边界测试。

维护者运行：`node --test tests/*.cjs`。无构建任务；另需检查JS语法和manifest本地文件引用。审核细节见《安全审核报告.md》，扫描范围与结果见 `security-scan.json`。
